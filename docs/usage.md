## 起動と終了

起動すると、画面の右下に立ち絵が現れ、macOS ではメニューバーに、Windows では通知領域にまりもの形のアイコンが出ます（[メニューバーと通知領域のアイコン](#メニューバーと通知領域のアイコン)を参照）。marimo は macOS では Dock にもアプリの切り替え（Cmd+Tab）にも出ず、Windows ではタスクバーに出ません。常に他のウィンドウより手前に表示されます。すでに起動しているときにもう一度起動すると、二つ目は何もせずに終わり、アイコンから隠していた窓があれば出し直します。

終了するときは、右クリックメニューか、アイコンのメニューの「終了」を選びます。

## ログイン時に起動する

ログインのたびに手で起動しなくて済むよう、自動起動を有効にできます。macOS では `/Applications` に置いた `marimo.app` を、Windows ではインストーラで入れた `%LOCALAPPDATA%\marimo\marimo.exe` を起動してから、立ち絵を右クリックして「ログイン時に起動」を選びます。

macOS では、`~/Library/LaunchAgents/com.marimo.desktop.plist` に LaunchAgent（ログイン時に macOS がプログラムを起動するための設定ファイル）を置きます。この plist は、有効にした時点で動いている実行ファイルのパスを指します。このため、`marimo.app` を別の場所へ移したときは、一度無効にしてから有効にし直してください。

Windows では、レジストリの `HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Run` に、有効にした時点で動いている `marimo.exe` のパスを登録します。`target\release\marimo.exe` から起動したまま有効にすると、ビルド用のフォルダの実行ファイルが登録されてしまうので、インストーラで入れた方から起動してください。

どちらの OS でも既定では無効で、marimo が勝手にログイン項目を増やすことはありません。

## メニューバーと通知領域のアイコン

marimo は、macOS ではメニューバーに、Windows では通知領域に、まりもの形の小さなアイコンを出します。アイコンを左クリックすると、立ち絵とパネルの窓を隠し、もう一度押すと出し直します。隠している間も状態の記録は続き、出し直したときには今の状態が出ます。macOS では、窓を出し直しても、使っているアプリからキーボードの入力先を奪いません。隠したことは保存しないので、marimo を起動し直すといつも窓が出た状態から始まります。

アイコンを右クリックすると、次のメニューが出ます。

| 項目 | 働き |
| --- | --- |
| marimo を隠す、marimo を表示 | 窓を隠すか出し直します。今の状態に合わせて、どちらか一方の名前で出ます |
| 絵を表示 | 立ち絵を出すかどうかを切り替えます（[表示を切り替える](#表示を切り替える)を参照） |
| 詳細を表示、件数だけ表示 | パネルの行の出し方を切り替えます（[表示を切り替える](#表示を切り替える)を参照） |
| 終了 | marimo を終了します |

アイコンは、手を貸す必要のあるセッションがあるときだけ色が付きます。

| アイコン | 状態 |
| --- | --- |
| 緑のまりもにオレンジの「！」 | 承認待ちのセッションがあります |
| 緑のまりもに赤の「！」 | 承認待ちは無く、エラーのセッションがあります |
| macOS では黒一色、Windows では緑のまりも | どちらも無いとき |

承認待ちとエラーが両方あるときは、立ち絵の表情と同じ優先度で承認待ちのアイコンが出ます。アイコンは窓を隠している間も状態に合わせて変わるので、窓を隠したままでも気付けます。

ふだんの macOS のアイコンは黒一色のテンプレート画像で、メニューバーの明るさに合わせて macOS が白か黒で描きます。Windows の通知領域はこの描き分けをしないので、ふだんから緑で塗ったアイコンを使います。Windows では、アイコンが通知領域の隠れた部分（タスクバーの `^` を押すと出る場所）に入ることがあります。

## 右クリックメニュー

立ち絵やパネルの上で右クリックすると、次のメニューが出ます。選んだ内容は保存され、次回の起動でも使われます（保存先は[ファイルとデータ](development.md#ファイルとデータ)を参照）。

| 項目 | 働き |
| --- | --- |
| 絵を表示 | 立ち絵と吹き出しを出すかどうかを切り替えます |
| 詳細を表示 | パネルに、セッションを 1 行ずつ並べます |
| 件数だけ表示 | パネルを、状態ごとの件数だけの 1 行に畳みます |
| 背景の不透明度… | パネルの地の濃さを変える小さな窓を開きます（[背景の不透明度](#背景の不透明度)を参照） |
| 吹き出し | 承認待ち、完了、エラーの吹き出しを出すかどうかと、吹き出しを自動で閉じるまでの時間を選びます（[吹き出し](#吹き出し)を参照） |
| 始まった順に並べる、状態の順に並べる、更新の新しい順に並べる | パネルの行の並べ方を切り替えます（[行の並べ方](#行の並べ方)を参照） |
| 小（0.6）、中（1.0）、大（1.5）、特大（2.0）、最大（2.5） | 立ち絵の大きさを切り替えます |
| キャラクター | 立ち絵のキャラクターを選びます。選ぶとその場で切り替わります |
| ログイン時に起動 | ログイン時の自動起動を切り替えます。既定は無効です |
| 終了 | marimo を終了します |

倍率 1.0 のときの立ち絵の枠の大きさは、[自分のキャラクターを作る](customize.md#自分のキャラクターを作る)に書いています。メニューのほかに、立ち絵の上で Cmd キー（macOS 以外では Ctrl キー）を押しながらマウスのホイールを回すと、0.1 刻みで 0.6 から 2.5 までの間を変えられます。大きさを変えても窓の右下の角は動かず、画面からはみ出す分は画面の内側へ戻ります。パネルと吹き出しの文字の大きさは変わりません。

## 表示を切り替える

「絵を表示」「詳細を表示」「件数だけ表示」の三つの項目は、右クリックメニューとアイコンのメニューの両方にあります。パネルの右上にも、いつも「詳細」と「件数」の二つのボタンが出ます。今の表示の方が明るく示され、暗い方を押すとそちらへ切り替わります。行が一つも無いときも、このボタンは消えません。どこで変えても同じ設定が変わって保存され、どのメニューを開いても今の状態に印が付きます。アイコンのメニューで選んだ内容はアプリがその場で反映して保存するので、起動した直後に選んだ場合や、続けて素早く選んだ場合も失われません。行の並べ方は、右クリックメニューとパネルの左上のボタンで切り替えます（[行の並べ方](#行の並べ方)を参照）。アイコンのメニューには並べ方の項目はありません。

「絵を表示」と、「詳細を表示」か「件数だけ表示」のどちらかは、別々に選べます。既定は、立ち絵を出したうえでの詳細の表示です。パネルはどの組み合わせでも出ていて、パネルを出さない表示はありません。パネルのボタンで切り替えられるのは詳細と件数だけで、立ち絵を出すかどうかはメニューの「絵を表示」で切り替えます。

一行表示にはファイル名やコマンドの一部が出るので、画面を人に見せるときなどは「件数だけ表示」へすぐ切り替えられます。件数の行そのものにはファイル名もコマンドも出ず、マウスを載せたときだけ詳細が重なって出ます。窓ごと見えなくしたいときは、メニューバーのアイコンを押して隠します。

「絵を表示」を外すと立ち絵と吹き出しが見えなくなります。窓の大きさとパネルの位置は変わりません。パネルの余白を右クリックするとメニューが開き、ドラッグすると窓を動かせます。立ち絵が隠れている間は吹き出しが出ません。「絵を表示」を戻したとき、吹き出しのきっかけになった状態がまだ続いていれば、その吹き出しが出ます。立ち絵の上でホイールを回す操作は使えないので、大きさはメニューから変えてください。

### 背景の不透明度

右クリックメニューの「背景の不透明度…」を選ぶと、パネルの上辺のボタンの列のすぐ上に小さな窓が開きます。窓の中のスライダーで、パネルの地の濃さを 20% から 100% までの間で 5% 刻みに変えられます。既定は 80% です。スライダーを動かしている間はパネルの地がその場で変わり、スライダーの左の「背景 80%」のような表示で今の値が分かります。値は、スライダーからマウスのボタンを離したときに保存されます。

薄くなるのはパネルとその上辺のボタンの列の地だけで、文字やアイコン、状態の色の点は薄くなりません。件数の行にマウスを載せたときに重なって出る詳細も一緒に薄くなりますが、下の行の文字と混ざって読めなくならないよう、パネルより濃く保ちます。パネルが 80% 以上のときは不透明で、いちばん薄くしても 85% までしか薄くなりません。吹き出しの濃さは変わりません。

パネルが窓の上端近くまで伸びていてボタンの列の上に場所が無いときは、小さな窓はボタンの列の下に、パネルの上の方の行へ重ねて開きます。小さな窓は、右端の「×」のボタンを押すか、Esc キーを押すか、小さな窓の外を押すと閉じます。ほかのアプリへ切り替えたときも閉じます。アイコンのメニューには、この項目はありません。

## パネルの見方

**詳細**の表示では、待機以外のセッションを 1 セッション 1 行で並べます。並べ方は選べ、既定では始まった順に新しいセッションほど上に出します（[行の並べ方](#行の並べ方)を参照）。各行は 2 段になっています。

- 1 段目には、状態の色の点、名前、チャットの題名、コンテキスト使用率が並びます。名前は作業フォルダを含む git リポジトリの名前で、リポジトリの外では作業フォルダ名になります。git worktree の中で作業しているときも、worktree のフォルダ名ではなく元のリポジトリの名前を出します。題名は名前の後ろに小さく薄い文字で出し、幅が足りないときは題名から省略します。題名が分からないセッションでは名前だけが出ます。コンテキスト使用率は、上限が分かるときは小さなバーとパーセントで出し、80% 以上になるとバーの色が変わります。上限が分からないときは、トークン数を枠付きの数値（例 `45.2k`）で出して、バーと見分けられるようにしています。デスクトップアプリの Code タブのセッションは上限が分からないので、トークン数で出ます。同じ会話を CLI（端末で動かすコマンドラインインターフェース）で開いて statusLine から上限が一度届くと、それ以降はパーセントで出せるようになります。marimo はモデル名から上限を推し量ることはしません。
- 2 段目には、今何をしているかの要約が 1 行で出ます。Bash なら Claude が付けた説明（description）、ファイルの読み書きなら作業フォルダからの相対パス、応答中なら文章の冒頭です。
- 2 段目の右、コンテキスト使用率の真下には、そのセッションに最後にフックが届いてからの時間が「今」「5分前」「2時間前」のように小さく出ます。パネルは 30 秒ごとに描き直すので、1 分より細かくは出しません。マウスを載せると、最後に届いた時刻が出ます。statusLine の入力はこの時刻を進めません。
- 2 段目の左、状態の点の真下には、Claude Code と Codex のどちらのセッションかを示す小さなアプリのアイコンが出ます。アイコンは marimo に同梱せず、手元に入っている Claude と Codex のデスクトップアプリから読みます（読み方は[marimo が読むもの](development.md#marimo-が読むもの)を参照）。macOS では Codex のアプリが ChatGPT.app として入っているので、ChatGPT のアイコンになることがあります。アプリが入っていないなどでアイコンを読めないときは、代わりに `CC`（Claude Code）か `CX`（Codex）の小さな文字の印が出ます。
- 行にマウスを載せるとツールチップが出て、チャットの題名、作業フォルダのフルパス、要約の全文、コマンドや引数そのものを読めます。

題名とコンテキスト使用率をどこから取るかは、[題名とコンテキスト使用率の取り方](development.md#題名とコンテキスト使用率の取り方)に書いています。デスクトップアプリの Code タブでは、Claude Code の更新で題名が出なくなることがあります。

行の数に上限はありません。行が増えるとパネルが上へ伸びるだけで、立ち絵の位置は動きません。パネルが窓の上端近くまで伸びると、それ以上は伸びずに、行の並びをマウスのホイールでスクロールできるようになります。立ち絵を出している間は、吹き出しがパネルの右上に重ならないよう、窓の上端から吹き出しの高さの分だけ下で止まります。スクロールバーはパネルの右端に細く出ます。スクロールした位置は、パネルが描き直されても保たれます。行が減ってその位置まで届かなくなったときは、いちばん下までスクロールした位置になります。行が一つも無いときも、パネルは消えずに「動いているセッションはありません」という薄い 1 行を出します。

**件数**の表示では、状態ごとの件数を色の点と一緒に 1 行で出します（例「承認待ち 1 · 作業中 3 · 完了 2」）。0 件の状態は出しません。この行にマウスを載せると、詳細の表示が上に重なって現れます。重なって出る詳細にも行の数の上限は無く、窓に収まらないときはその中をホイールでスクロールできます。スクロールしている間も、マウスが重なった詳細の上にあれば閉じません。行を押すと、承認待ち、エラー、完了の中でいちばん優先度の高いセッションへ移動します。

件数の行も、数える状態が一つも無いときは「動いているセッションはありません」の 1 行になります。

### 行の並べ方

行の並べ方は、次の三つから選べます。右クリックメニューの項目か、パネルの左上に出る「開始順」「状態順」「更新順」の三つのボタンで切り替えます。ボタンは右上の「詳細」「件数」と同じ形で、今の並べ方の方が明るく示されます。マウスを載せると、それぞれの並べ方の説明がツールチップで出ます。選んだ並べ方は、詳細の表示にも、件数の行に重なって出る詳細にも効きます。

| 並べ方 | メニューの項目 | 働き |
| --- | --- | --- |
| 開始順 | 始まった順に並べる | 始まった時刻の新しいセッションほど上に出します。既定の並べ方です |
| 状態順 | 状態の順に並べる | 状態の優先度の高い順（[状態の種類と優先度](../README.md#状態の種類と優先度)を参照）に並べ、同じ状態の中では最後の更新が新しいものを上に出します。見たと示した直後の薄い完了の行は、ほかの行より下に置きます |
| 更新順 | 更新の新しい順に並べる | 最後に更新されたセッションほど上に出します |

開始順では、状態が変わっても行の順が入れ替わらないので、見ている行が動くことはありません。新しいセッションは一番上に加わります。パネルが窓に収まっている間は、パネルが下端を固定して上へ伸びるので、既にある行の画面上の位置も変わりません。開始時刻が記録されていないセッションは、次の出来事が届くまでは一番下に並びます。状態順と更新順では、状態や更新の時刻が変わるたびに行が入れ替わります。どの並べ方でも、時刻が同じで順の決まらない行どうしが、描き直すたびに入れ替わることはありません。

## セッションへ移動する

パネルの行を押すと、そのセッションが動いているウィンドウやタブへ移動します。Codex のセッションでも同じです。macOS では次のように動きます。

| セッションを動かしている場所 | 移動のしかた |
| --- | --- |
| Terminal.app、iTerm2 | TTY（端末の装置名）が一致するタブを AppleScript で探して前面に出します |
| VS Code の統合ターミナル | 作業フォルダを開いているウィンドウを前面に出します。VS Code から派生したエディタでは、記録したアプリを開きます |
| デスクトップアプリの Code タブ | アプリを前面に出します。特定の会話を開く公式の手段が見つからないためです |
| それ以外 | 記録したアプリを前面に出します。Codex のデスクトップアプリから動いているセッションも、ここにあたります。アプリも分からなければ何もしません |

Terminal.app と iTerm2 のタブを選ぶとき、初回に macOS が marimo へのオートメーションの許可を求めます。許可しなかった場合は、アプリを前面に出すところまでで止まります。

Windows では次のように動きます。デスクトップアプリの Code タブのセッションは、表の「それ以外」の経路でデスクトップアプリのウィンドウが前面に出ます。

| セッションを動かしている場所 | 移動のしかた |
| --- | --- |
| Windows Terminal | そのセッションのタブがあるウィンドウを前面に出します。Windows Terminal には外からタブを選ぶ公開された手段が無いので、タブまでは選びません |
| コマンドプロンプトや PowerShell の従来のコンソール（conhost） | そのコンソールのウィンドウを前面に出します |
| VS Code とその派生（Cursor、VSCodium、Windsurf など）の統合ターミナル | エディタに作業フォルダを渡して、そのフォルダを開いているウィンドウを前面に出します |
| それ以外 | Claude Code の祖先のプロセスを近い順にたどり、最初に見つかったアプリのウィンドウを前面に出します。エクスプローラーより上はたどりません |

フックは、セッションの開始時とプロンプトを送ったときに、Claude Code が動いているコンソールのウィンドウと祖先のプロセスを記録します。行を押したとき、記録したウィンドウやプロセスが既に閉じられていたり、別のものに入れ替わっていたりすれば、そのウィンドウは使いません。また Windows は、他のアプリのウィンドウが前面に出ることを制限しているので、前面に出る代わりにタスクバーのボタンが点滅するだけになることがあります。

## 完了の既読

完了した行は、行を押してセッションへ移動するか、完了の吹き出しを押して閉じると「既読」になります。押した直後に行が消えると何を押したのか見失うので、既読になった行は 3 分間だけ、その場所で薄く表示されます。3 分を過ぎると畳まれて見えなくなります。既読の完了は、立ち絵の表情でも待機として扱われます。

既読の記録は `~/.marimo/acknowledged.json` に保存されるので、アプリを再起動しても同じ完了を知らせ直すことはありません。再起動の前に既読にした完了の行は、再起動の後は薄く残さずに最初から畳んだ状態になります。記録は、そのきっかけ（どのセッションが、いつから、どの状態か）が続いている間だけ残ります。同じセッションが次に完了すれば、新しい完了として再び未読で出ます。

承認待ちとエラーの行は、押しても消えません。それぞれ承認されるまで、または状態が変わるまで残ります。

## 吹き出し

吹き出しは、既定では、きっかけの状態が全体の状態として続いている間、出たままになります。承認待ちなら承認されるまで、完了なら次のプロンプトまで、エラーなら状態が変わるまでです。別の作業から戻ってきたときに気づけるよう、時間では消えません。同じきっかけの間はセリフも変わりません。

吹き出しを押すと閉じ、同じセッションの同じ状態の間は再び出ません。複数のセッションが該当するときは、全体の状態として選ばれたセッションについて出し、それが解決すると次のセッションへ切り替わります。

吹き出しは立ち絵の枠のすぐ上に出ます。Clawd のように背の低いキャラクターでは、長いセリフの吹き出しが左のパネルに重なることがあるので、そのときだけパネルの上端より上へ持ち上げて出します。

右クリックメニューの「吹き出し」では、次の二つを選べます。選んだ内容は保存され、次回の起動でも使われます。

| 項目 | 働き |
| --- | --- |
| 承認待ちを出す、完了を出す、エラーを出す | 外した種類では吹き出しを出しません。パネルの行と立ち絵の表情は変わりません。外した種類の吹き出しは既読にならないので、あとで戻せば、状態が続いている間は出ます。既定はすべて出します |
| 押すまで表示、10 秒で閉じる、30 秒で閉じる、1 分で閉じる、5 分で閉じる | 吹き出しが出てから自動で閉じるまでの時間です。既定は押すまで表示です。時間で閉じた吹き出しは、押して閉じたときと違い、見たものとは扱いません。完了の行は薄くならず、同じきっかけの間は出し直されません。立ち絵を隠している間は時間を数えず、戻したときに数え直します |

立ち絵を押したときのひとことは、この設定に関わらず出ます。

セリフの変え方は、[セリフを変える](customize.md#セリフを変える)に書いています。

## 立ち絵の表情

立ち絵の表情は、全体の状態に合わせて変わります（[状態の種類と優先度](../README.md#状態の種類と優先度)を参照）。待機中と作業中は、瞬きと呼吸のような小さな動きがあります。表情の切り替えは、瞬きを除いてクロスフェード（前の絵を薄くしながら次の絵へ移すこと）で行います。

小春の作業中の顔は、使っているツールによって、真剣に集中した顔、書いたものがうまく動いて嬉しそうに笑う顔、眼鏡をかけて文字を目で追う顔、興味深そうに調べる顔、横目で手順を確かめる顔、相手の話に耳を傾ける顔、ウインクして「任せて」という顔に変わります。ツールを使わずに考えたり応答を書いたりしている間は考え込む顔になり、それ以外のツールでは手元を読む顔になります。どのツールでどの顔になるかは、[自分のキャラクターを作る](customize.md#自分のキャラクターを作る)の `rules.working_tools` に書いています。待機中は 20 秒から 60 秒に一度ほど、小春なら視線を外す、髪を耳にかける、あくびをする、マグカップでひと息つく、顎に手を添える、伸びをする、鼻歌を歌う、のどれかの仕草を 5 秒から 8 秒ほど、文庫本を読む、うたた寝をする、のどちらかの仕草を 8 秒から 12 秒ほど見せます。

完了と承認待ちとエラーの顔は、吹き出しのセリフと同じ分類で、状態の中の違いによって変えられます。小春は、15 分以上かかった作業が終わったとき（`done.long`）は目を閉じて伸びをする顔、利用制限に達して止まったとき（`error.rate_limit`）はマグカップでひと息つく顔になります。分類の一覧は[セリフを変える](customize.md#セリフを変える)に、表情の指定の仕方は `rules.variants` に書いています。

Clawd の表情の出し方は小春と同じで、作業中の顔は使っているツールによって変わります。承認待ちでは片手を挙げて「！」を、完了では両手を挙げてきらきらを出し、待機中は左右を見る、跳ねる、眠る、伸びをする、のどれかの仕草を見せます。ドット絵は大きさを変えてもぼやけないように描き、呼吸のような伸び縮みはしません。

## 立ち絵への操作

- **押す** 立ち絵を押すと、照れた笑顔を 2.5 秒ほど見せて、ひとことの吹き出しを出します。承認待ちなどの知らせの吹き出しが出ている間は、それを上書きせずに表情だけを変えます。
- **マウスを載せる** 作業中に立ち絵へマウスを載せると、こちらを見る顔になります。マウスを離すと、少し間を置いて元の表情へ戻ります。
- **ドラッグする** 押したまま少し動かすと、窓ごと移動できます。位置は `~/.marimo/window.json` に保存され、次回も同じ場所に出ます。保存した位置がモニタの構成の変化などで画面の外になった場合は、画面の右下へ戻ります。

窓の透明な部分へのクリックは、下にある別のウィンドウへそのまま通ります。クリックを受け取るのは、立ち絵の不透明な部分、パネル、吹き出しの上だけです。「絵を表示」を外しているときは立ち絵が隠れているので、パネルの上だけになります。

## 利用制限の表示

5 時間と 7 日の利用制限は、Claude Code の statusLine から届きます。CLI では、Claude Code が statusLine を呼ぶたびに、入力に含まれる利用制限の値を marimo が保存します。設定は何も要りません。デスクトップアプリの Code タブでは statusLine が呼ばれないので、CLI も使っているときだけ、CLI の statusLine が最後に届けた値が出ます。

### 利用制限の行

パネルの下端には、`5h 23% · 7d 84%` のように 5 時間と 7 日の利用制限の使用率が出て、その横に最後に値が更新された時刻（例 `14:05 更新`）が出ます。この行はアカウント全体で一つだけで、すべてのセッションが待機中でも表示されます。表示できる値が無いときは、行を出しません。

Codex の利用制限が記録されているときは、同じ行に Claude Code の値と Codex の値を並べ、それぞれの先頭にアプリのアイコン（読めないときは `CC` と `CX` の文字の印）を付けます。たとえば Claude のアイコンの後に `5h 12% · 7d 30%`、Codex のアイコンの後に `7d 13%` のように出ます。Codex の窓の名前は Codex が送ってきた窓の長さから決め、日の単位で割り切れれば `7d`、時間の単位で割り切れれば `5h`、それ以外は分の数（例 `90m`）にします。長さが送られてこなかった窓は、名前を付けずに割合だけを出します。どちらか一方の値しか出せないときは、その一方だけをアイコンと一緒に出します。Codex の値が一度も記録されていなければ、アイコンは付けず、Claude Code の値だけを出します。右端の時刻は、出している値のうち最も新しい更新の時刻です。それぞれの値にマウスを載せると、その値の更新の時刻がツールチップで出ます。Codex の値の更新の時刻は、Codex の記録にその値が書かれた時刻です（[ファイルとデータ](development.md#ファイルとデータ)の `observed_at` を参照）。

最後の更新から 30 分以上経った値は、実際の値から離れている可能性が高いので薄く表示されます。Claude Code と Codex の値が並んでいるときは、古さを値ごとに判断し、30 分以上経った方の値だけを薄くします。リセットの時刻を過ぎた枠の値は意味を持たなくなるので消えます。

## 更新する

README の [4. 更新する](../README.md#4-更新する)で使う更新用のスクリプト `tools/update.sh` と `tools/update.ps1` の動きを説明します。スクリプトは、GitHub Actions の CI（継続的インテグレーション。push のたびに自動でテストやビルドを行う仕組み）が main のコミットについてビルドしたものを、GitHub のリリースから取ってきて入れ替えます。手元ではビルドしないので、Rust や Node.js は要りません。スクリプトは次のことを順に行います。

1. `git pull --ff-only` で main の最新を取り込みます。
2. 取り込んだコミットのビルドを一時フォルダへ取ってきます。コミットのハッシュの先頭 12 文字を使った `build-<12 文字>` という名前のリリースから、macOS では `marimo-macos-arm64.tar.gz` を、Windows では `marimo-windows-x64.zip` を、チェックサムを書いた `SHA256SUMS` と一緒に取ってきます。チェックサムが合わなければ、何も変えずに止まります。リポジトリの `origin` が GitHub のリポジトリを指していればそのリポジトリのリリースを、そうでなければ marimo の元のリポジトリのリリースを探すので、フォークからでも使えます。
3. 起動している marimo を終了します。macOS では、10 秒ほど待っても終わらなければ、アプリを差し替えずに止まります。Windows では、終わらなければそのまま進み、動いているアプリを閉じる処理をインストーラに任せます。インストーラも閉じられなければ、アプリは差し替わらずに失敗を表示します。
4. アプリを差し替えます。macOS では、新しい `marimo.app` を `/Applications` の中へ別の名前でコピーしてから、古い `/Applications/marimo.app` と入れ替えます。Windows では、NSIS（Windows 向けのインストーラを作る仕組み）のインストーラを画面を出さずに（`/S`）実行して、`%LOCALAPPDATA%\marimo\marimo.exe` を入れ直します。
5. 取ってきた `marimo-hook` で `install` を実行し、`~/.marimo/bin/marimo-hook`（Windows では `marimo-hook.exe`）を新しいものに差し替えます。`install` は自分自身をこの場所へコピーするので、一時フォルダから実行してもフックは動き続けます。
6. marimo を起動し直し、一時フォルダを消します。

CI は、アプリに入らないファイル（`.md` のファイル、`docs/` と `tools/` と `art/` の中のファイル、`LICENSE-` で始まるファイル、`.gitignore`）だけを変えたコミットをビルドしません。スクリプトは、取り込んだコミットから main の履歴をさかのぼり、それら以外を変えた最後のコミットのビルドを取ってきます。

CI がビルドするのは、arm64 の Mac（Apple シリコンの Mac）向けと x64 の Windows 向けだけです。Intel の Mac では、下の `--build` を付けて手元でビルドしてください。

main へ push してから CI がビルドを公開するまでには、テストとビルドの時間がかかります。リリースが公開された直後の数十秒は、ダウンロードが失敗することがあるので、スクリプトは 10 秒おきに 1 分まで確かめ直します。それでも取り込んだコミットのビルドが無いときは、CI がこのコミットのビルドを終えていないか、ビルドに失敗していることと、GitHub Actions の実行の一覧のアドレスを表示し、アプリに触れずに 0 以外の終了コードで終わります。macOS では `--wait` を、Windows では `-Wait` を付けると、30 秒おきに確かめながら最大 30 分待ち、ビルドができあがれば続けます。30 分経ってもできあがらなければ、同じ表示をして終わります。

Windows では、応答を受け取る前に接続が切れたときに、5 秒おいて 3 回までやり直します。取ってくるのに失敗したときは、marimo を終了せず、アプリも差し替えません。`install` が失敗したときは、アプリを差し替えて起動し直したうえで、0 以外の終了コードで終わります。表示された理由を確かめてから、スクリプトをもう一度実行してください。

取り込む前に、今のブランチが `main` であることと、Git で管理しているファイルにコミットしていない変更が無いことを確かめます。どちらかを満たさなければ、何もせずに理由を表示して終わります。Git で管理していないファイルがあってもかまいません。macOS では `--no-pull` を、Windows では `-NoPull` を付けると、確認と取り込みを省き、今チェックアウトしているコミットのビルドを取ってきます。CI がビルドするのは main へ push されたコミットだけなので、この使い方ができるのは main を通ったコミットに限られます。

### 手元でビルドして更新する

macOS では `--build` を、Windows では `-Build` を付けると、ビルドを取ってくる代わりに手元でビルドします。ネットワークにつながらないときや、main 以外のブランチを試すときに使います。main 以外のブランチを試すときは、macOS では `--no-pull --build` を、Windows では `-NoPull -Build` を付けて、今チェックアウトしているものをそのままビルドします。ビルドには[必要なもの](development.md#必要なもの)のツールが要ります。

このときは、2. の代わりに `marimo-hook` とアプリをビルドします。画面部分の依存は、`package-lock.json` を書き換えない `npm ci` で入れ直します。アプリは、macOS では `marimo.app` だけを、Windows では NSIS のインストーラだけを作ります。環境変数 `CARGO_TARGET_DIR` を設定していれば、できあがったものをその下から探します。ビルドに失敗したときは、marimo を終了せず、アプリも差し替えません。`install` が失敗したときは、ビルドした `marimo-hook` で `install` を実行し直してください。

Windows では、スクリプトを使わずに、手元でビルドし直した NSIS のインストーラをもう一度実行して更新することもできます。このときはフックのコマンドを差し替えるために、ビルドした `marimo-hook` で `install` も実行し直します。

### 更新のあとに確かめること

すでに登録済みなら、`install` は settings.json も Codex の `hooks.json` も変えないので、Codex の `/hooks` で信頼し直す必要はありません（[既存の設定の守り方](development.md#既存の設定の守り方)を参照）。

## 困ったとき

### デスクトップアプリで利用制限が出ない

デスクトップアプリの Code タブでは statusLine が呼ばれないので、Claude Code の利用制限は届きません。CLI を併用している場合は、CLI の statusLine が最後に書いた値が出ます（[利用制限の表示](#利用制限の表示)を参照）。

### 利用制限が更新されない

利用制限の値は、Claude Code が statusLine を呼んだときにだけ更新されます。statusLine は応答のたびに呼ばれるので、手元で作業していない間は値も変わらず、30 分以上経つと薄く表示されます（[利用制限の行](#利用制限の行)を参照）。

CLI で作業しているのに値が変わらないときは、`--dry-run` を付けて `install` を実行し、statusLine についての表示を確かめます。既存の statusLine を包めなかった場合や、marimo-hook のパスのせいで登録できなかった場合は、その理由と、Claude Code の利用制限が表示されないことが出ます（[statusLine の包み方](development.md#statusline-の包み方)を参照）。

### セッションの状態が出ない

待機中のセッションは、パネルに行を出さない決まりです。作業中、承認待ち、完了、エラーのどれかになっているはずなのに出ないときは、次を順に確かめます。

1. フックが登録されているかを確かめます。`--dry-run` を付けて `install` を実行すると、ファイルを変えずに「登録済みのフック」の一覧を表示します。

   ```bash
   ~/.marimo/bin/marimo-hook install --dry-run
   ```

2. Claude Code のバージョンを `claude --version` で確かめます。marimo のフックは exec form で登録するので、`args` を解釈しない古い Claude Code では正しく呼ばれません（必要な版は[動作環境](../README.md#動作環境)を参照）。
3. `CLAUDE_CONFIG_DIR` を使っている場合は、`install` がその下の settings.json を書き換えたかどうかを確かめます。別の設定ファイルを使っているなら、`--settings` で指定して登録し直します（[サブコマンドと設定ファイルの場所](development.md#サブコマンドと設定ファイルの場所)を参照）。
4. `~/.marimo/sessions/` にファイルができているかを確かめます。ファイルがあるのに表示されない場合は、アプリを起動し直します。
5. 登録より前から開いていたセッションで状態が出ない場合は、そのセッションを開き直してみてください。
6. クラウドで動くセッションと Cowork では表示できません（[動作環境](../README.md#動作環境)を参照）。

### 終わったはずのセッションが残り続ける

Claude Code が SessionEnd を送らずに終わった場合は、そのセッションの行がしばらく残ります。アプリは起動したときと、その後 10 分ごとに、24 時間更新のないセッションのファイルを消すので、遅くとも 1 日ほどで行は消えます。書き込みの途中で残った一時ファイルも、24 時間経ったものは同じときに消します。

長く放っておいただけのセッションが消えても、そのセッションで作業を再開すれば、次のフックでファイルが作り直されて行が戻ります。すぐに消したいときは、marimo を終了してから `~/.marimo/sessions/` の該当するファイルを削除します。

SubagentStart と SubagentStop のフックが登録されていない設定では、サブエージェントが終わった後も 30 分ほど作業中のまま残ります。`install` を実行し直すと、足りないフックだけが追加されます。

### 窓が画面の外へ出てしまった

窓が見つからないときは、marimo を終了して `~/.marimo/window.json` を削除してから起動し直すと、既定の位置（主モニタの右下）に出ます。

### 状態をすべてやり直したい

marimo を終了してから、次のファイルを必要に応じて削除します。どれも消してかまわず、次の起動やフックで作り直されます。

| 削除するもの | 元に戻るもの |
| --- | --- |
| `~/.marimo/sessions/` の中のファイル | セッションの一覧。以降のフックで作り直されます |
| `~/.marimo/acknowledged.json` | 既読の記録 |
| `~/.marimo/window.json` | 窓の位置 |
| `~/.marimo/display.json` | 倍率、立ち絵とパネルの表示、行の並べ方、パネルの背景の不透明度、吹き出しの種類と表示時間、キャラクター、立ち絵の枠の縦横比の設定 |
| `~/.marimo/rate_limits.json` | 利用制限の値 |
| `~/.marimo/codex_rate_limits.json` | Codex の利用制限の値 |

`~/.marimo/bin/` は削除しないでください。フックがここを指しているためです（[install が行うこと](development.md#install-が行うこと)を参照）。消してしまった場合は、`install` を実行し直せば戻ります。

## アンインストール

1. 立ち絵を右クリックして「ログイン時に起動」を有効にしていたら、先に無効にします。これで macOS では LaunchAgent の plist が、Windows ではレジストリの登録が取り除かれます。
2. 右クリックメニューか、メニューバー（Windows では通知領域）のアイコンのメニューの「終了」で marimo を終了します。
3. フックと statusLine の登録を解除します。

   ```bash
   ~/.marimo/bin/marimo-hook uninstall
   ```

   `uninstall` が取り除くものは、[uninstall が行うこと](development.md#uninstall-が行うこと)を参照してください。

4. macOS では `/Applications/marimo.app` を削除します。Windows では、設定の「アプリ」から marimo をアンインストールします。
5. `uninstall` は実行ファイルとデータを残すので、不要なら `~/.marimo` フォルダを手で削除します。`uninstall` の最後に、消してよいパスが表示されます。settings.json のバックアップ（`settings.json.marimo-backup-*`）も、不要になったら手で削除してください。
