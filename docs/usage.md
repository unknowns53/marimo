## 起動と終了

起動すると、画面の右下に立ち絵が現れ、macOS ではメニューバーに、Windows では通知領域にまりもの形のアイコンが出ます（[メニューバーと通知領域のアイコン](#メニューバーと通知領域のアイコン)を参照）。marimo は macOS では Dock にもアプリの切り替え（Cmd+Tab）にも出ず、Windows ではタスクバーに出ません。常に他のウィンドウより手前に表示されます。すでに起動しているときにもう一度起動すると、二つ目は何もせずに終わり、アイコンから隠していた窓があれば出し直します。

登録より前から開いていたセッションの状態が出ない場合は、そのセッションを開き直してみてください。

## ログイン時に起動する

ログインのたびに手で起動しなくて済むよう、自動起動を有効にできます。macOS では `/Applications` に置いた `marimo.app` を、Windows ではインストーラで入れた `%LOCALAPPDATA%\marimo\marimo.exe` を起動してから、立ち絵を右クリックして「ログイン時に起動」を選びます。

macOS では、`~/Library/LaunchAgents/com.marimo.desktop.plist` に LaunchAgent（ログイン時に macOS がプログラムを起動するための設定ファイル）を置きます。この plist は、有効にした時点で動いている実行ファイルのパスを指します。このため、`marimo.app` を別の場所へ移したときは、一度無効にしてから有効にし直してください。

Windows では、レジストリの `HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Run` に、有効にした時点で動いている `marimo.exe` のパスを登録します。`target\release\marimo.exe` から起動したまま有効にすると、ビルド用のフォルダの実行ファイルが登録されてしまうので、インストーラで入れた方から起動してください。

どちらの OS でも既定では無効で、marimo が勝手にログイン項目を増やすことはありません。

## メニューバーと通知領域のアイコン

marimo は、macOS ではメニューバーに、Windows では通知領域に、まりもの形の小さなアイコンを出します。アイコンを左クリックすると、立ち絵とパネルの窓を隠し、もう一度押すと出し直します。隠している間も状態の記録は続き、出し直したときには今の状態が出ます。macOS では、窓を出し直しても、使っているアプリからキーボードの入力先を奪いません。隠したことは保存しないので、marimo を起動し直すといつも窓が出た状態から始まります。marimo をもう一度起動したときも、隠していた窓が出ます。

アイコンを右クリックすると、次のメニューが出ます。

| 項目 | 働き |
| --- | --- |
| marimo を隠す、marimo を表示 | 窓を隠すか出し直します。今の状態に合わせて、どちらか一方の名前で出ます |
| 絵を表示 | 右クリックメニューの同じ項目と同じです |
| 詳細を表示、件数だけ表示 | 右クリックメニューの同じ項目と同じです。どちらか一方に印が付きます |
| 終了 | marimo を終了します |

アイコンは、手を貸す必要のあるセッションがあるときだけ色が付きます。

| アイコン | 状態 |
| --- | --- |
| 緑のまりもにオレンジの「！」 | 承認待ちのセッションがあります |
| 緑のまりもに赤の「！」 | 承認待ちは無く、エラーのセッションがあります |
| macOS では黒一色、Windows では緑のまりも | どちらも無いとき |

承認待ちとエラーが両方あるときは、立ち絵の表情と同じ優先度で承認待ちのアイコンが出ます。アイコンは窓を隠している間も状態に合わせて変わるので、窓を隠したままでも気付けます。

ふだんの macOS のアイコンは黒一色のテンプレート画像で、メニューバーの明るさに合わせて macOS が白か黒で描きます。Windows の通知領域はこの描き分けをしないので、ふだんから緑で塗ったアイコンを使います。Windows では、アイコンが通知領域の隠れた部分（タスクバーの `^` を押すと出る場所）に入ることがあります。Windows での動きは実機で確かめていません。

## 右クリックメニュー

立ち絵やパネルの上で右クリックすると、次のメニューが出ます。選んだ内容は `~/.marimo/display.json` に保存され、次回の起動でも使われます（ログイン時の起動だけは macOS の LaunchAgent で管理します）。表示の三つの項目は、[メニューバーと通知領域のアイコン](#メニューバーと通知領域のアイコン)のメニューにもあります。

| 項目 | 働き |
| --- | --- |
| 絵を表示 | 立ち絵と吹き出しを出すかどうかを切り替えます。既定は表示です |
| 詳細を表示 | パネルに、待機以外のセッションを 1 行ずつ並べます。既定はこちらです |
| 件数だけ表示 | パネルを、状態ごとの件数だけの 1 行に畳みます |
| 小（0.6）、中（1.0）、大（1.5）、特大（2.0）、最大（2.5） | 立ち絵の大きさを切り替えます |
| キャラクター | 立ち絵のキャラクターを、小春と Clawd から選びます。選ぶとその場で切り替わります |
| 利用制限を API から取得 | 利用制限を Anthropic の利用量の API から取るかどうかを切り替えます。既定は無効です |
| ログイン時に起動 | ログイン時の自動起動を切り替えます。既定は無効です |
| 終了 | marimo を終了します |

立ち絵の枠は、倍率 1.0 のとき幅 180 ピクセルで、高さはキャラクターの素材の縦横比で決まります。小春は 180×270 ピクセル、Clawd は 180×90 ピクセルです。メニューのほかに、立ち絵の上で Cmd キー（macOS 以外では Ctrl キー）を押しながらマウスのホイールを回すと、0.1 刻みで 0.6 から 2.5 までの間を変えられます。大きさを変えても窓の右下の角は動かず、画面からはみ出す分は画面の内側へ戻ります。パネルと吹き出しの文字の大きさは変わりません。

## 表示を切り替える

「絵を表示」「詳細を表示」「件数だけ表示」は、このメニュー、右クリックメニュー、パネルの「詳細」と「件数」のボタンのどれで変えても同じ設定を変え、どのメニューを開いても今の状態に印が付きます。

「絵を表示」と、「詳細を表示」か「件数だけ表示」のどちらかは、別々に選べます。パネルはどの組み合わせでも出ていて、パネルを出さない表示はありません。

一行表示にはファイル名やコマンドの一部が出るので、画面を人に見せるときなどは「件数だけ表示」へすぐ切り替えられます。件数の行そのものにはファイル名もコマンドも出ず、マウスを載せたときだけ詳細が重なって出ます。窓ごと見えなくしたいときは、メニューバーのアイコンを押して隠します。

「絵を表示」を外すと立ち絵と吹き出しが見えなくなり、立ち絵のあった場所へのクリックは下のウィンドウへそのまま通ります。窓の大きさとパネルの位置は変わりません。パネルの余白を右クリックするとメニューが開き、ドラッグすると窓を動かせます。立ち絵が隠れている間は吹き出しが出ません。「絵を表示」を戻したとき、吹き出しのきっかけになった状態がまだ続いていれば、その吹き出しが出ます。立ち絵の上でホイールを回す操作は使えないので、大きさはメニューから変えてください。

パネルの右上には、いつも「詳細」と「件数」の二つのボタンが出ます。今の表示の方が明るく示され、暗い方を押すとそちらへ切り替わります。行が一つも無いときも、このボタンは消えません。立ち絵を出すかどうかは、右クリックメニューの「絵を表示」で切り替えます。

## パネルの見方

**詳細**の表示では、待機以外のセッションを始まった順に並べ、新しいセッションほど上に出します。状態が変わっても行の順は入れ替わらないので、見ている行が動くことはありません。marimo を更新する前から動いていたセッションは始まった時刻の記録を持たないので、次の出来事が届くまでは一番下に並びます。各行は 2 段になっています。

- 1 段目には、状態の色の点、名前、チャットの題名、コンテキスト使用率が並びます。名前は作業フォルダを含む git リポジトリの名前で、リポジトリの外では作業フォルダ名になります。git worktree の中で作業しているときも、worktree のフォルダ名ではなく元のリポジトリの名前を出します。題名は名前の後ろに小さく薄い文字で出し、幅が足りないときは題名から省略します。題名が分からないセッションでは名前だけが出ます。コンテキスト使用率は、上限が分かるときは小さなバーとパーセントで出し、80% 以上になるとバーの色が変わります。上限が分からないときは、トークン数を枠付きの数値（例 `45.2k`）で出して、バーと見分けられるようにしています。marimo はモデル名から上限を推し量ることはしません。
- 2 段目には、今何をしているかの要約が 1 行で出ます。Bash なら Claude が付けた説明（description）、ファイルの読み書きなら作業フォルダからの相対パス、応答中なら文章の冒頭です。
- 2 段目の右、コンテキスト使用率の真下には、そのセッションに最後にフックが届いてからの時間が「今」「5分前」「2時間前」のように小さく出ます。パネルは 30 秒ごとに描き直すので、1 分より細かくは出しません。マウスを載せると、最後に届いた時刻が出ます。statusLine の入力はこの時刻を進めません。
- 2 段目の左、状態の点の真下には、Claude Code と Codex のどちらのセッションかを示す小さなアプリのアイコンが出ます。アイコンは marimo に同梱せず、起動したときに手元に入っている Claude と Codex のデスクトップアプリから読みます。macOS では、NSWorkspace が bundle id `com.anthropic.claudefordesktop` と `com.openai.codex` のアプリに対して返すアイコンを使います（Codex のアプリは ChatGPT.app として入っているので、ChatGPT のアイコンになることがあります）。Windows では、パッケージ `Claude_pzs8sxrjxfjjc` と `OpenAI.Codex_2p2nqsd0c76g0` のロゴを使います。アプリが入っていないなどでアイコンを読めないときは、代わりに `CC`（Claude Code）か `CX`（Codex）の小さな文字の印が出ます。
- 行にマウスを載せるとツールチップが出て、チャットの題名、作業フォルダのフルパス、要約の全文、コマンドや引数そのものを読めます。

デスクトップアプリの Code タブでは statusLine が動かないため、marimo はコンテキスト使用率を会話ログ（transcript。Claude Code がセッションごとに書く JSON Lines 形式の記録）から数えます。このときモデルのコンテキストの上限が分からないので、パーセントではなくトークン数を出します。同じ会話を CLI で開いて statusLine から上限が一度届くと、それ以降はパーセントで出せるようになります。

行は全体で 5 行までで、それを超えた分は「ほか N 件」にまとめます。5 行に収まらないときは、未読の行を既読の行より先に、そのうえで承認待ち、エラー、作業中、完了の順に選ぶので、承認待ちのセッションから先に表示されます。選んだ行も、始まった順に並べます。行が増えるとパネルが上へ伸びるだけで、立ち絵の位置は動きません。新しいセッションは一番上に加わるので、既にある行の画面上の位置も変わりません。行が一つも無いときも、パネルは消えずに「動いているセッションはありません」という薄い 1 行を出します。

**件数**の表示では、状態ごとの件数を色の点と一緒に 1 行で出します（例「承認待ち 1 · 作業中 3 · 完了 2」）。0 件の状態は出しません。この行にマウスを載せると、詳細の表示が上に重なって現れます。行を押すと、承認待ち、エラー、完了の中でいちばん優先度の高いセッションへ移動します。

件数の行も、数える状態が一つも無いときは「動いているセッションはありません」の 1 行になります。

## セッションへ移動する

パネルの行を押すと、そのセッションが動いているウィンドウやタブへ移動します。macOS では次のように動きます。

| セッションを動かしている場所 | 移動のしかた |
| --- | --- |
| Terminal.app、iTerm2 | TTY（端末の装置名）が一致するタブを AppleScript で探して前面に出します |
| VS Code の統合ターミナル | 作業フォルダを開いているウィンドウを前面に出します。VS Code から派生したエディタでは、記録したアプリを開きます |
| デスクトップアプリの Code タブ | アプリを前面に出します。特定の会話を開く公式の手段が見つからないためです |
| それ以外 | 記録したアプリを前面に出します。アプリも分からなければ何もしません |

Terminal.app での見分け方は実機で確かめてあり、iTerm2 と VS Code の見分け方はそれぞれのアプリの文書に基づいています。Terminal.app と iTerm2 のタブを選ぶとき、初回に macOS が marimo へのオートメーションの許可を求めます。許可しなかった場合は、アプリを前面に出すところまでで止まります。

Codex のセッションの行を押したときの移動のしかたは、Claude Code のセッションと同じです（[セッションへ移動する](#セッションへ移動する)を参照）。Codex のデスクトップアプリ（bundle id は `com.openai.codex`）から動いているセッションでは、表の「それ以外」にあたり、そのアプリを前面に出します。

Windows では次のように動きます。実機で確かめているのは、デスクトップアプリの Code タブのセッションで、表の「それ以外」の経路によりデスクトップアプリのウィンドウが前面に出ることだけです。ほかの行は確かめていません。

| セッションを動かしている場所 | 移動のしかた |
| --- | --- |
| Windows Terminal | そのセッションのタブがあるウィンドウを前面に出します。Windows Terminal には外からタブを選ぶ公開された手段が無いので、タブまでは選びません |
| コマンドプロンプトや PowerShell の従来のコンソール（conhost） | そのコンソールのウィンドウを前面に出します |
| VS Code とその派生（Cursor、VSCodium、Windsurf など）の統合ターミナル | エディタに作業フォルダを渡して、そのフォルダを開いているウィンドウを前面に出します |
| それ以外 | Claude Code の祖先のプロセスを近い順にたどり、最初に見つかったアプリのウィンドウを前面に出します。エクスプローラーより上はたどりません |

フックは、セッションの開始時とプロンプトを送ったときに、Claude Code が動いているコンソールのウィンドウと祖先のプロセスを記録します。行を押したとき、記録したウィンドウやプロセスが既に閉じられていたり、別のものに入れ替わっていたりすれば、そのウィンドウは使いません。また Windows は、他のアプリのウィンドウが前面に出ることを制限しているので、前面に出る代わりにタスクバーのボタンが点滅するだけになることがあります。

## 完了の既読

完了した行は、行を押してセッションへ移動するか、完了の吹き出しを押して閉じると「既読」になります。押した直後に行が消えると何を押したのか見失うので、既読になった行は 3 分間だけ、その場所で薄く表示されます。3 分を過ぎると畳まれて見えなくなります。既読の完了は、立ち絵の表情でも待機として扱われます。

既読の記録は `~/.marimo/acknowledged.json` に保存されるので、アプリを再起動しても同じ完了を知らせ直すことはありません。再起動の前に既読にした完了の行は、再起動の後は薄く残さずに最初から畳んだ状態になります。記録は、そのきっかけ（どのセッションが、いつから、どの状態か）が続いている間だけ残ります。同じセッションが次に完了すれば、新しい完了として再び未読で出ます。

承認待ちとエラーの行は、押しても消えません。それぞれ承認されるまで、または状態が変わるまで残ります。

## 吹き出し

吹き出しは、きっかけの状態が全体の状態として続いている間、出たままになります。承認待ちなら承認されるまで、完了なら次のプロンプトまで、エラーなら状態が変わるまでです。別の作業から戻ってきたときに気づけるよう、時間では消えません。同じきっかけの間はセリフも変わりません。

吹き出しを押すと閉じ、同じセッションの同じ状態の間は再び出ません。複数のセッションが該当するときは、全体の状態として選ばれたセッションについて出し、それが解決すると次のセッションへ切り替わります。

吹き出しは立ち絵の枠のすぐ上に出ます。Clawd のように背の低いキャラクターでは、長いセリフの吹き出しが左のパネルに重なることがあるので、そのときだけパネルの上端より上へ持ち上げて出します。

## 立ち絵への操作

- **押す** 立ち絵を押すと、照れた笑顔を 2.5 秒ほど見せて、ひとことの吹き出しを出します。承認待ちなどの知らせの吹き出しが出ている間は、それを上書きせずに表情だけを変えます。
- **マウスを載せる** 作業中に立ち絵へマウスを載せると、こちらを見る顔になります。マウスを離すと、少し間を置いて元の表情へ戻ります。
- **ドラッグする** 押したまま少し動かすと、窓ごと移動できます。位置は `~/.marimo/window.json` に保存され、次回も同じ場所に出ます。保存した位置がモニタの構成の変化などで画面の外になった場合は、画面の右下へ戻ります。

窓の透明な部分へのクリックは、下にある別のウィンドウへそのまま通ります。クリックを受け取るのは、立ち絵の不透明な部分、パネル、吹き出しの上だけです。「絵を表示」を外しているときは立ち絵が隠れているので、パネルの上だけになります。

## 利用制限の表示

5 時間と 7 日の利用制限は、次の二つの情報源から届きます。どちらも同じ `~/.marimo/rate_limits.json` へ書くので、両方が動いているときは後から書いた方の値が出ます。

1. **statusLine** CLI では、Claude Code が statusLine を呼ぶたびに、入力に含まれる利用制限の値を marimo が保存します。設定は何も要りません。
2. **利用量の API** 右クリックメニューの「利用制限を API から取得」を有効にすると、アプリ自身が Anthropic の API へ利用量を問い合わせます。statusLine が動かないデスクトップアプリの Code タブで利用制限を見たいときに使います。

利用制限の API から取った値が statusLine の値と揃うかどうかは、確かめていません。

### 利用制限の行

パネルの下端には、`5h 23% · 7d 84%` のように 5 時間と 7 日の利用制限の使用率が出て、その横に最後に値が更新された時刻（例 `14:05 更新`）が出ます。この行はアカウント全体で一つだけで、すべてのセッションが待機中でも表示されます。値が取れていないときは行を出しません。

Codex の利用制限が記録されているときは、同じ行に Claude Code の値と Codex の値を並べ、それぞれの先頭にアプリのアイコン（読めないときは `CC` と `CX` の文字の印）を付けます。たとえば Claude のアイコンの後に `5h 12% · 7d 30%`、Codex のアイコンの後に `7d 13%` のように出ます。Codex の窓の名前は Codex が送ってきた窓の長さから決め、日の単位で割り切れれば `7d`、時間の単位で割り切れれば `5h`、それ以外は分の数（例 `90m`）にします。長さが送られてこなかった窓は、名前を付けずに割合だけを出します。どちらか一方の値しか出せないときは、その一方だけをアイコンと一緒に出します。Codex の値が一度も記録されていなければ、アイコンは付けず、Claude Code の値だけを以前と同じ形で出します。右端の時刻は、出している値のうち最も新しい更新の時刻です。それぞれの値にマウスを載せると、その値の更新の時刻がツールチップで出ます。Codex の値の更新の時刻は、値を読んだ rollout の行の時刻です。

最後の更新から 30 分以上経った値は、実際の値から離れている可能性が高いので薄く表示されます。Claude Code と Codex の値が並んでいるときは、古さを値ごとに判断し、30 分以上経った方の値だけを薄くします。リセットの時刻を過ぎた枠の値は意味を持たなくなるので消えます。

### API からの取得のしくみ

有効にするとすぐに一度問い合わせ、その後は 5 分おきに `https://api.anthropic.com/api/oauth/usage` を呼びます。応答の `five_hour` と `seven_day` の使用率とリセットの時刻を、statusLine と同じ形で保存します。

このエンドポイントは公開された API ではなく、文書もありません。予告なく変わったり使えなくなったりする可能性があります。応答の形が想定と違うときは、何も書かずに次の周期を待ちます。

| 結果 | 次の問い合わせ |
| --- | --- |
| 成功 | 5 分後。間隔が広がっていた場合も 5 分に戻します |
| 429（呼びすぎ） | 間隔を倍にして、最大 30 分まで広げます。応答に秒数の `Retry-After` があれば、それより早くは呼びません（上限 6 時間） |
| 401 や 403（トークンが拒まれた） | 今の間隔のまま待ち、次はトークンを読み直します |
| 通信の失敗 | 今の間隔のまま待ちます |

要求は 10 秒で打ち切り、HTTPS でしか送らず、リダイレクト（別の URL への転送）は追いません。リダイレクト先へトークンを送らないためです。

### トークンの扱い

API を呼ぶには、Claude Code がログイン時に保存した OAuth（外部のサービスに、パスワードを渡さずにアクセスを許可するための仕組み）のアクセストークンが要ります。marimo はこれを次のように扱います。

- **読む場所** macOS では、ログインキーチェーンの汎用パスワード（サービス名 `Claude Code-credentials`）だけを読みます。macOS 以外では、`CLAUDE_CONFIG_DIR` があればその下の、なければ `~/.claude/` の `.credentials.json` を読みます。中身のうち、`claudeAiOauth` の `accessToken`、`expiresAt`、`scopes` だけを使います。
- **読むだけ** marimo はトークンを更新も保存もしません。トークンを更新するとリフレッシュトークンが入れ替わり、Claude Code のログインが切れてしまうからです。期限が切れていたら API を呼ばずに、Claude Code が更新するのを待ちます。`scopes` に `user:profile` が無い場合も呼びません。
- **メモリにだけ置く** 読んだトークンはメモリにだけ持ち、期限が切れるか、401 や 403 で拒まれるまで使い回します。ファイルにもログにもエラーの文にも出しません。オプションを無効にすると、持っていたトークンを捨てます。
- **送り先** トークンは `api.anthropic.com` への要求にだけ使います。

### キーチェーンの確認

macOS では、有効にしたあと最初にトークンを読むとき、キーチェーンの確認の画面が出ます。marimo は `security` コマンドを経由せずに Security フレームワークを直接呼ぶので、確認の画面には marimo の名前が出るように作られています。この表示は実機では確かめていません。

- 「常に許可」を選ぶと、次からは確認が出なくなります。「許可」を選んだ場合は、トークンを読み直すたびに確認が出ます。トークンはメモリに持って使い回すので、読み直すのは、アプリを起動したり設定を有効にし直したりした後の最初の一回と、期限が切れたときと、拒まれたときです。
- 確認を拒むか取り消すと、marimo は問い合わせを止めます。保存した設定は変えないので、再開したいときはメニューで一度無効にしてから有効にし直します。
- [ad-hoc 署名](development.md#ad-hoc-署名について)のため、アプリをビルドし直すと確認がもう一度出ます。

## 更新する

スクリプトは次のことを順に行います。

1. `git pull --ff-only` で main の最新を取り込みます。
2. `marimo-hook` とアプリをビルドします。画面部分の依存は、`package-lock.json` を書き換えない `npm ci` で入れ直します。アプリは、macOS では `marimo.app` だけを、Windows では NSIS のインストーラだけを作ります。環境変数 `CARGO_TARGET_DIR` を設定していれば、できあがったものをその下から探します。
3. 両方のビルドが成功したら、起動している marimo を終了します。macOS では、10 秒ほど待っても終わらなければ、アプリを差し替えずに止まります。Windows では、終わらなければそのまま進み、動いているアプリを閉じる処理をインストーラに任せます。インストーラも閉じられなければ、アプリは差し替わらずに失敗を表示します。
4. アプリを差し替えます。macOS では、新しい `marimo.app` を `/Applications` の中へ別の名前でコピーしてから、古い `/Applications/marimo.app` と入れ替えます。Windows では、NSIS のインストーラを画面を出さずに（`/S`）実行して、`%LOCALAPPDATA%\marimo\marimo.exe` を入れ直します。
5. ビルドしたばかりの `marimo-hook` で `install` を実行し、`~/.marimo/bin/marimo-hook` を新しいものに差し替えます。
6. marimo を起動し直します。

ビルドに失敗したときは、marimo を終了せず、アプリも差し替えません。`install` が失敗したときは、アプリを差し替えて起動し直したうえで、0 以外の終了コードで終わります。表示された理由を確かめてから、`install` を実行し直してください。

取り込む前に、今のブランチが `main` であることと、Git で管理しているファイルにコミットしていない変更が無いことを確かめます。どちらかを満たさなければ、何もせずに理由を表示して終わります。Git で管理していないファイルがあってもかまいません。main 以外のブランチを試すときは、macOS では `--no-pull` を、Windows では `-NoPull` を付けて実行します。このときは確認と取り込みを省き、今チェックアウトしているものをそのままビルドします。

`install` は同じ場所の実行ファイルでやり直すだけなので、すでに登録済みなら settings.json も Codex の `hooks.json` も変わりません。Codex の `/hooks` で信頼し直す必要もありません。

macOS では、ビルドし直したアプリの [ad-hoc 署名](development.md#ad-hoc-署名について)が変わるので、[利用制限を API から取得](#利用制限の表示)を使っている場合は、キーチェーンの確認がもう一度出ることがあります（[キーチェーンの確認がまた出る](#キーチェーンの確認がまた出る)を参照）。

どちらのスクリプトも、実機で更新が最後まで通ることを確かめています。

## 困ったとき

### デスクトップアプリで利用制限が出ない

デスクトップアプリの Code タブでは statusLine が呼ばれないので、statusLine からは利用制限が届きません。右クリックメニューの「利用制限を API から取得」を有効にしてください。CLI を併用している場合は、CLI の statusLine が最後に書いた値も表示に使われます。

### キーチェーンの確認がまた出る

アプリをビルドし直すと ad-hoc 署名が変わるので、macOS は以前の「常に許可」を当てはめません。もう一度「常に許可」を選んでください。確認を拒んでしまった場合は、メニューで「利用制限を API から取得」を一度無効にしてから有効にし直すと、問い合わせを再開します。

### セッションの状態が出ない

待機中のセッションは、パネルに行を出さない決まりです。作業中、承認待ち、完了、エラーのどれかになっているはずなのに出ないときは、次を順に確かめます。

1. フックが登録されているかを確かめます。`--dry-run` を付けて `install` を実行すると、ファイルを変えずに「登録済みのフック」の一覧を表示します。

   ```bash
   ~/.marimo/bin/marimo-hook install --dry-run
   ```

2. Claude Code のバージョンが 2.1.139 以降かを `claude --version` で確かめます。marimo のフックは exec form で登録するので、`args` を解釈しない古い Claude Code では正しく呼ばれません。
3. `CLAUDE_CONFIG_DIR` を使っている場合は、`install` がその下の settings.json を書き換えたかどうかを確かめます。別の設定ファイルを使っているなら、`--settings` で指定して登録し直します。
4. `~/.marimo/sessions/` にファイルができているかを確かめます。ファイルがあるのに表示されない場合は、アプリを起動し直します。
5. 登録より前から開いていたセッションで状態が出ない場合は、そのセッションを開き直してみてください。
6. クラウドで動くセッションと Cowork では、フックが届かないので表示できません。

### 終わったはずのセッションが残り続ける

Claude Code が SessionEnd を送らずに終わった場合は、そのセッションの行がしばらく残ります。アプリは起動したときと、その後 10 分ごとに、24 時間更新のないセッションのファイルを消すので、遅くとも 1 日ほどで行は消えます。書き込みの途中で残った一時ファイルも、24 時間経ったものは同じときに消します。

長く放っておいただけのセッションが消えても、そのセッションで作業を再開すれば、次のフックでファイルが作り直されて行が戻ります。すぐに消したいときは、marimo を終了してから `~/.marimo/sessions/` の該当するファイルを削除します。

SubagentStart と SubagentStop のフックを登録していない以前の版の設定では、サブエージェントの終わりが分からず、終わった後も 30 分ほど作業中のまま残ります。以前の版で `install` を実行していた場合は、`install` を実行し直してください。足りないイベントだけが追加され、すでに登録してあるフックはそのまま残ります。

### 窓が画面の外へ出てしまった

保存した位置がどのモニタにも入らない場合、marimo は起動時に窓を画面の右下へ戻します。それでも見つからないときは、marimo を終了して `~/.marimo/window.json` を削除してから起動し直すと、既定の位置（主モニタの右下）に出ます。

### 状態をすべてやり直したい

marimo を終了してから、次のファイルを必要に応じて削除します。どれも消してかまわず、次の起動やフックで作り直されます。

| 削除するもの | 元に戻るもの |
| --- | --- |
| `~/.marimo/sessions/` の中のファイル | セッションの一覧。以降のフックで作り直されます |
| `~/.marimo/acknowledged.json` | 既読の記録 |
| `~/.marimo/window.json` | 窓の位置 |
| `~/.marimo/display.json` | 倍率、立ち絵とパネルの表示、API からの取得、キャラクターの設定 |
| `~/.marimo/rate_limits.json` | 利用制限の値 |

`~/.marimo/bin/` は削除しないでください。settings.json のフックがここを指しているので、消すとフックが動かなくなります。消してしまった場合は、`install` を実行し直せば戻ります。

## アンインストール

1. 立ち絵を右クリックして「ログイン時に起動」を有効にしていたら、先に無効にします。これで macOS では LaunchAgent の plist が、Windows ではレジストリの登録が取り除かれます。
2. 右クリックメニューか、メニューバー（Windows では通知領域）のアイコンのメニューの「終了」で marimo を終了します。
3. フックと statusLine の登録を解除します。

   ```bash
   ~/.marimo/bin/marimo-hook uninstall
   ```

   `uninstall` が取り除くものは、[uninstall が行うこと](development.md#uninstall-が行うこと)を参照してください。

4. macOS では `/Applications/marimo.app` を削除します。Windows では、設定の「アプリ」から marimo をアンインストールします。
5. `uninstall` は実行ファイルとデータを残すので、不要なら `~/.marimo` フォルダを手で削除します。`uninstall` の最後に、消してよいパスが表示されます。settings.json のバックアップ（`settings.json.marimo-backup-*`）も、不要になったら手で削除してください。
