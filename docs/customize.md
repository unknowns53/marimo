# 表示を変更する

吹き出しのセリフ、立ち絵のキャラクター、素材の変更方法を記載しています。概要と導入の手順は [README](../README.md) を参照してください。

- [セリフを変える](#セリフを変える)
- [自分のキャラクターを作る](#自分のキャラクターを作る)
- [素材を作り直す](#素材を作り直す)

## セリフを変える

吹き出しのセリフは、選択しているキャラクターの既定のものを使用します。自分のセリフを使用するときは、`~/.marimo/dialogue.json` に**変更したい分類のみ**を記入します。分類ごとに、このファイルにあればそれを、無ければ既定のセリフを使用します。

たとえば、長い作業が終わったときと、承認を待っているときのセリフのみを変更するには、以下のように記入します。

```json
{
  "done.long": [
    "{folder} の作業、{duration}かかって終わったよ。お茶でもどう？"
  ],
  "waiting": [
    "{folder} で手を貸してほしいの。",
    "{folder} があなたの返事を待っているよ。"
  ]
}
```

各分類の値は、1 行以上の文字列の配列にします。候補が複数あれば、その中から一つが選ばれます。ファイルは新しい吹き出しを表示するときに読み直されるため、アプリを再起動しなくても反映されます。ファイルが読めないときや、形式の合わない分類は無視され、既定のセリフで動作し続けます。

分類はドット区切りで、細かい分類にセリフが無ければ親の分類を使用します。たとえば `waiting.permission` が無ければ `waiting` を使用します。

| 分類 | 使用される場面 |
| --- | --- |
| `waiting.permission` | コマンドやファイル操作の実行許可を待っているとき |
| `waiting.question` | Claude が質問をして回答を待っているとき |
| `waiting.plan` | 計画の承認を待っているとき |
| `waiting` | その他の承認待ち |
| `done.short` | 2 分未満で完了したとき |
| `done` | 2 分以上 15 分未満で完了したとき、またはかかった時間が分からないとき |
| `done.long` | 15 分以上かかって完了したとき |
| `error.rate_limit` | 利用制限に達して止まったとき |
| `error` | その他のエラー |

完了までの時間は、プロンプトを送信してから応答が終わるまでの時間です。セリフの中には、以下の二つの差し込みを記入できます。

| 差し込み | 置き換わる内容 |
| --- | --- |
| `{folder}` | リポジトリ名。リポジトリ外では作業フォルダ名（パスの最後の部分） |
| `{duration}` | 完了までにかかった時間。「25 分」「1 時間 10 分」の形で、1 分未満は「1 分足らず」になります。分からないときは空になります |

既定のセリフはキャラクターごとにあり、小春のものは `assets/character/koharu/dialogue.json`、Clawd のものは `assets/character/clawd/dialogue.json` で全体を確認でき、自分のファイルを作成するときの手本になります。`~/.marimo/dialogue.json` はキャラクターごとに分かれておらず、どのキャラクターを選択していても同じ上書きが適用されます。

起動時に `~/.marimo/dialogue.json` が、marimo の古いバージョンが丸ごと書き出した既定のセリフと内容が完全に同じだった場合は、編集されていないものとみなして `dialogue.json.unused-default` へ名前を変えて退避します。このファイルが残っていると、既定のセリフを修正しても利用者に反映されないためです。

## 自分のキャラクターを作る

立ち絵の素材は、リポジトリの `assets/character/` の下にキャラクターごとのフォルダで置き、ビルド時にアプリへ組み込まれます。組み込みのキャラクターは、小春（秋月小春）の `koharu` と Clawd の `clawd` です。コードを変更せずにキャラクターを追加でき、以下の手順のあとにアプリを再ビルドします。

1. `assets/character/` の下に、キャラクターの名前（英小文字で記載する識別名の ID）のフォルダを作成し、画像、`manifest.json`、既定のセリフの `dialogue.json` を置きます。
2. `assets/character/index.json` の配列に、その名前を追加します。配列の順が設定のウィンドウの「キャラクター」に並ぶ順になり、先頭のキャラクターが既定になります。

起動時に、保存した名前がこの一覧に無い場合や、そのキャラクターの `manifest.json` を読めない場合は、先頭（既定）のキャラクターを読み込みます。`index.json` そのものを読めない場合も、既定の `koharu` を読み込み、設定のウィンドウの一覧にも `koharu` を表示します。設定のウィンドウからの切り替えに失敗したときは、変更前のキャラクターのままです。表情の画像を読めないときの扱いは、この節の最後に記載しています。

素材は、すべて同じキャンバスサイズの透過 PNG（背景を透明にできる画像の形式）にします。立ち絵の領域は倍率 1.0 で幅 108 ピクセルに固定し、高さはキャンバスの縦横比から決定します。小春は 800×1200 ピクセルなので領域は 108×162、Clawd は 216×180 ピクセルなので 108×90 です。ウィンドウの高さも領域に合わせて変わります。吹き出しは領域の上端のすぐ上に表示されるため、キャンバスの上の余白は、頭の上に描く飾りの分のみにします。クリックを受け取る範囲は、各画像のアルファ値（不透明度）から自動で作成されるため、別途用意する必要はありません。

`manifest.json` には、どの画像をどの場面で使用するかを記載します。コードを変更せずに表情を増やしたりキャラクターを替えたりできるよう、表情の名前はすべてここに持たせています。小春の `manifest.json` を例に、項目の意味を説明します。

| 項目 | 意味 |
| --- | --- |
| `name` | キャラクターの名前（ID）。フォルダの名前と同じにします |
| `display_name` | 設定のウィンドウの「キャラクター」に表示する名前。省略すると `name` を使用します |
| `pixelated` | `true` にすると、画像を拡大や縮小しても画素をぼかさずに描き、呼吸のような伸び縮みもしません。ドット絵の素材に使用します |
| `mode` | 描き方の種類。`"standing"`（立ち絵）のみが動作します。`"sprite"` は型の定義のみがあり、描画は実装されていないため、指定するとキャラクターが表示されません |
| `canvas` | 素材のキャンバスの `width` と `height`。立ち絵の領域の縦横比に使用します |
| `expressions` | 表情の名前ごとに、画像ファイル `image` と、瞬きの差分 `blink` を記載します。`blink` を記載した表情のみが瞬きします |
| `rules.status` | 五つの状態（`idle`、`working`、`waiting`、`done`、`error`）ごとの基本の表情 |
| `rules.variants` | セリフの分類名（[セリフを変える](#セリフを変える)の表にあるもの）ごとに、その分類のときに使用する表情を記載します。たとえば `"done.long": "idle_stretch"` と記載すると、15 分以上かかって終わったときに `idle_stretch` を表示します。状態の基本の表情より優先し、細かい分類が無ければ基本の表情になります（セリフと異なり、親の分類は使用しません）。画像を読めない表情も基本の表情で代用します。既定では、小春が `done.long` と `error.rate_limit` に使用しています |
| `rules.working_tools` | 作業中に、ツール名の一覧 `tools` のいずれかを使用していたら表情 `expression` に切り替えます。既定では Bash と PowerShell で `working_focus`、Edit、Write、NotebookEdit、Codex のファイルの編集の apply_patch で `working_write`、Read、Grep、Glob で `working_read`、WebSearch と WebFetch で `working_curious`、TodoWrite、Codex の update_plan、ToolSearch、Skill で `working_plan`、MCP のツールで `working_listen`、サブエージェントを起動する Agent、Task、spawn_agent（Codex）で `working_delegate` を使用します。ツール名の末尾に `*` を付けると、その前までが一致するツールすべてに適用されます。MCP のツールは `mcp__<サーバー名>__<ツール名>` の名前で届くため、`mcp__*` と記載すればまとめて指定できます。完全一致の指定があれば、そちらを優先します。`max_ms` を記載すると、その表情を続けて表示する時間の上限（ミリ秒）になり、過ぎたら作業中の基本の表情へ戻します。サブエージェントの実行中は同じツールが何分も続き、ウインクが続くと不自然なため、既定では `working_delegate` を 30000 にしています |
| `rules.working_no_tool` | 作業中に、ツールを使用していないとき（考えているときや応答を書いているとき）の表情。既定では `working_think` を使用します。省略すると `rules.status` の作業中の表情のままです |
| `rules.min_switch_ms` | 作業中の表情を切り替える最短の間隔（ミリ秒）。ツールは数秒ごとに変わるため、ちらつかないように間を空けます。既定は 4000 です |
| `rules.idle_gestures` | 待機中の仕草。`interval_ms` は仕草の間隔の最小と最大、`gestures` は仕草の表情と、表示する時間 `duration_ms` の最小と最大です。直前と同じ仕草は続けて選ばれません |
| `rules.hover` | 状態ごとの、マウスを載せたときの表情。既定では作業中のみ `idle` を使用します |
| `rules.hover_release_ms` | マウスが離れてから元の表情へ戻すまでの時間。既定は 600 です |

表情の画像が読めなかったり、manifest に無かったりした場合は、その状態の基本の表情で、それも無ければ `idle` で代用します。最低限、`idle` の画像が一枚あれば動作します。

## 素材を作り直す

素材の作り直しには Python の仮想環境（プロジェクト専用に依存パッケージを導入する、独立した Python の環境）を使用します。リポジトリの直下で仮想環境を作成し、依存パッケージを導入します。バージョンは `tools/character/requirements.txt` で固定しています。

```bash
python3 -m venv .venv
.venv/bin/pip install -r tools/character/requirements.txt
```

この仮想環境は、アイコンを描き直すときにも使用します（[アイコンを描き直す](development.md#アイコンを描き直す)を参照）。

### 小春の素材

`tools/character/build.py` は、生成した基準の画像と表情の差分から、アプリで使用する透過 PNG のセットを作成するスクリプトです。表情の差分から顔の部分のみを切り出して基準の画像に合成するため、顔のみの差分では首から下が基準の画像と画素単位で同じになり、表情を切り替えても体がちらつきません。透明度は rembg（画像の背景を取り除く Python のライブラリ）の isnet-anime モデルで作成し、髪のエッジは pymatting（前景と背景の境界の透明度を推定するライブラリ）の closed-form matting で解き直して、背景の色がエッジに残らないようにします。

設定ファイルを渡して実行すると、設定ファイルの `out_dir`（小春では `assets/character/koharu`）へ PNG を書き出します。

```bash
.venv/bin/python tools/character/build.py tools/character/koharu.json
```

`--preview` に保存先を渡すと、暗い背景と明るい背景の両方に重ねた一覧画像も書き出します。髪のエッジに背景のグレーが残っていないかを目視で確認するときに使用します。

```bash
.venv/bin/python tools/character/build.py tools/character/koharu.json --preview preview.png
```

設定ファイル（小春は `tools/character/koharu.json`）には、以下の項目を記載します。

| 項目 | 意味 |
| --- | --- |
| `base` | 基準の立ち絵の画像 |
| `out_dir` | 書き出し先のフォルダ |
| `canvas` | 書き出す画像の幅と高さ |
| `rembg_model` | rembg のモデル名。省略すると `isnet-anime` を使用します |
| `face_ellipse` | 差分から切り出す顔の範囲を表す楕円の中心 `cx`、`cy` と半径 `rx`、`ry` |
| `states` | 書き出す画像ごとの作り方 |

`states` の各項目には、以下のいずれか一つを記載します。

| 書き方 | 作り方 |
| --- | --- |
| `{"source": "base"}` | 基準の画像をそのまま使用します |
| `{"face": "<画像>"}` | 差分の画像の顔の範囲のみを、基準の画像へ合成します |
| `{"face": "<画像>", "onto": "<状態>"}` | 顔の範囲を、基準の画像ではなく別の状態の合成結果へ合成します。作業中の表情の瞬きの差分などに使用します |
| `{"whole": "<画像>"}` | 合成せずにそのまま使用します。腕を描き足した承認待ちや、全体を描き直した仕草の差分に使用します |
| `{"whole": "<画像>", "keep": [[x0, y0, x1, y1]]}` | `whole` と同じですが、元の画像の座標で記載した矩形の中のみ、背景の色との差で前景と背景を分けます。rembg は人物から離れて浮く小さな記号を背景として消すため、鼻歌の仕草の音符のようなものを残すときに使用します |

採用した元の画像は `art/<キャラクター名>/` に置きます。`build.py` は PNG のみを書き出し、`manifest.json` は書き換えないため、表情を増やしたときは `manifest.json` も手動で編集します。

### Clawd の素材

Clawd の素材は、`tools/character/clawd.py` がドット絵を描いて作成します。形と表情はスクリプトの中に、画素を 1 文字ずつ並べた文字列として持ち、Pillow のみを使用します。ロゴの 1 画素はターミナルの文字の升目の 4 分の 1 で縦に長いため、横 2 マス、縦 4 マスで描いて、ターミナルで見るときと同じ縦横比にしています。実行すると `assets/character/clawd/` へ PNG を書き出し、`--preview` に保存先を渡すと、暗い背景と明るい背景に重ねた一覧画像も書き出します。

```bash
.venv/bin/python tools/character/clawd.py --preview preview.png
```

`clawd.py` も PNG のみを書き出すため、表情を増やしたときは `assets/character/clawd/manifest.json` も手動で編集します。
